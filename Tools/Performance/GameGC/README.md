# 全章 GC 检查与优化记录（2026-11-10）

已完成 16 个代表场景的同条件前后采样，以及尾声选项、谢幕文字、自动存档 3 个补充场景。16 个场景的常态主线程分配减少 95.9%–98.5%。第三章真实继续游戏另有两次前后采样，消除了字体图集重复复制带来的 128 MiB 托管分配。

本次处理持续分配来源和加载尖峰。项目原先已经启用增量 GC；没有修改 GC 模式、强制收集、帧率、剧情节奏或存档采样间隔。

**主要修改**

- 共用存档校验：连续枚举改为范围校验，避免装箱；复用无捕获委托、历史钉子标记和消息 ID，避免逐次构造字符串。实测完整 `EnsureData()` 从 328 B/次降到 0 B/次。保留旧存档和坏值修正行为。以后扩展枚举时，需要同步检查上下界及连续性。
- 第三章：复用物品列表和纸张 ID，保留每次读取当前状态；字体 Alpha8 图集直接使用 Unity 已有 CPU 数据，每个新字形读取前重新取得视图，避免动态扩容后引用旧地址。RGBA32 路径复用 alpha 缓冲，备用 GPU 读取路径完整释放临时资源。
- 第四章：事件在所属组件变化时重新绑定；答案标签清理列表、尾声选项尺寸、谢幕字形数组改为复用；头像逐像素调色不再创建数组。
- 可选组件探测改用 TryGetComponent，减少 Editor 中不存在组件时的分配。此项的 Player 收益可能不同。

配对记录位于 `validation/transitions-before-atlas.json` 和 `validation/transitions-after-atlas.json`。这些采样已包含前面的常态优化，唯一新增变量是字体图集读取修改。

|---|---:|---:|
| 第一次 | 140.67 | 6.88 |

两张 8192×8192 Alpha8 图集原先各复制 64 MiB 到托管数组，现在直接读取原数据。继续游戏的等待时间仍约 2.8–3.0 秒，包含既有过渡动画；本次没有证明加载时间或最大帧耗时同比改善。

**验证结果**

- 4,355 项存档枚举、旧数据修正、JSON 往返和调色结果检查通过；另有 51 组消息 ID／倒计时迁移检查通过。
- 168 组中日韩／拉丁文本字形位图逐像素一致；240 项纹理 alpha 检查通过，覆盖 Alpha8、RGBA32、ARGB32、动态尺寸变化和不可读纹理备用路径。
- 51 项列表刷新、多语言纸张标题、保存对象替换及事件禁用／重新启用检查通过。
- `OSChapter04FinalHealBackendQA`：195 项通过，包含真实输入、判定、结尾和多次磁盘存读档。
- `GameAutosavePersistenceQA`：48 项通过。修正了测试夹具的异步顺序：等待住宅自动切歌完成后再手动选择并暂停歌曲；增加保存前断言，避免把剧情切歌误判为读档丢失。没有为此修改运行时音乐逻辑。
- 所有磁盘写入使用独立测试目录；正式 Editor 自动存档及备份的 SHA-256 保持一致。详细证据在 `validation/`。

**测量范围与后续使用**

Unity 6000.4.11f1，Editor Mono，CPU Profiler 开启、Deep Profile 关闭，只统计主线程 PlayerLoop。常规场景预热 2 秒，记录 150 帧，分析末尾 120 帧；自动存档记录 600 帧并分析末尾 540 帧。历史汇总 JSON 的统一 note 尚写 150/120，以每场景 `frames` 和新工具说明为准。

场景包含脚本控制的行走、镜中演出和治疗进度，属于可重复的热点采样，并非逐句完整通关。原始结果保留 `samples`、调用归属、实际房间和窗口，便于复查。CPU 帧耗时含渲染等待等 Editor 因素，分配降幅不能直接换算成 FPS 提升。尚未做独立 Player／IL2CPP 的配对构建测量，也未把这些短采样当作长期内存泄漏结论。

当前剩余常态分配主要归属于 OS_Handle、第三章状态／窗口刷新及 UI；自动存档序列化也有合理的间歇分配。下一轮应优先在 Development Build 的真实长时间游玩中确认卡顿，再决定是否继续改这些逻辑。

在初始化完成的 Play Mode 中，执行菜单 `Tools > MrTGame > Performance > Run All-Chapter GC Audit` 可重跑 19 个场景。工具会临时切换关卡并使用独立存档，结果写入本目录的新时间戳子目录。运行结束后请退出 Play Mode，以结束测试会话。需要中断时调用 `OSGameGCQA.Cancel()`。
